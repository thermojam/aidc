## Порядок работы

Можно начинать **02 и 06**: исходная проверка 01 завершена, transformCallback не воспроизведён. ## Границы передачи

- Существующие проекты, материалы, расписания, голос, захват и агентные срезы переносить с проверкой сохранения поведения. Наличие кода не заменяет живую проверку.
- Переключение бесед во время потока остаётся запрещённым. Гонки проверять на разрешённых фоновых операциях; поддержку фонового переключения отдельно не добавлять.
- Задача 06 делает подтверждение состава обязательным в Rust; обновить контракт в продуктовом ТЗ. В 08 и 19 также зафиксировать новые правила хранения избранного и групп.
- Только синтетические данные и отдельный профиль macOS. Платные POST этим пакетом не разрешены; финансовые и сетевые исходы для UI воспроизводить синтетически.
- Проверка типов и сборка обязательны для реализации UI; существующие Rust-тесты — при изменении Rust/IPC/БД. Клавиатуру и визуальное поведение принимать в живом окне. Линтер не настроен; не создавать инфраструктуру только ради отчёта.
- Результаты записывать в журнал только после фактического выполнения, с ОС, сборкой и границами. Windows остаётся непроверенной до отдельного запуска на реальной машине.
- [Готовность P0](../codex-feature-map/issues/06-p0-readiness.md) сохраняет блокеры старого пакета 01–05; [интерактивный viewer](../codex-feature-map/issues/23-interactive-viewer.md) — 02/05. Номера этих задач относятся к codex-feature-map, а не к этому пакету. Они не изменены и не закрыты.
- Будущая проверка Windows остаётся в [существующей задаче](../codex-feature-map/issues/05-windows-smoke.md) и [сценарии платформы](../../docs/research/rea/smoke-windows.md): WebView2, DPI 100/150/200%, Snap, клавиатура и отрицательные IPC-проверки. Новую дублирующую задачу не создавать.
