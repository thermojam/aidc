# 13 — Перенести расписания в представление «Задачи»

**What to build:** Пользователь управляет расписаниями и открывает их результаты в отдельном представлении, сохраняя явное подтверждение каждого платного действия.

**Blocked by:** 03 — Показывать ошибки у соответствующей операции; 04 — Перестроить оболочку и навигацию проектов.

**Status:** ready-for-agent

- [ ] Создание и остановка расписания перенесены из нижнего аккордеона; наступившая задача имеет постоянный индикатор в навигации и доступный блок подтверждения.
- [ ] Подтверждение создаёт запуск и только готовит черновик исходной беседы; платная отправка требует обычной проверки контекста и отдельного действия.
- [ ] При активном потоке или отказе перехода текст задачи не попадает в другую беседу; пропущенные интервалы не создают серию автоматических запусков.
- [ ] Включение уведомлений остаётся явным; уведомления ОС не содержат текст задачи. Закрытое приложение не объявляется фоновым исполнителем.
- [ ] Нажатие уведомления текущего процесса открывает правильную задачу или сохранённый результат по ID запуска в новом представлении; проверен живой macOS-сценарий с синтетическим результатом.
- [ ] Существующие расписания, запуски и связи с ответами сохраняются после перезапуска и backup/restore; прежняя реализация не дублируется.
- [ ] Прошли проверка типов и сборка, при изменении Rust/БД — существующие тесты расписаний. Регрессия macOS записана в журнал; платные POST не выполнялись, Windows не засчитана.
