# 11 — Сделать историю удобной для чтения и восстановления

**What to build:** Пользователь читает длинные и частичные ответы, копирует код и возвращается к новым сообщениям без потери места чтения.

**Blocked by:** 03 — Показывать ошибки у соответствующей операции; 04 — Перестроить оболочку и навигацию проектов.

**Status:** ready-for-agent

- [ ] Markdown использует GFM с явным запретом HTML; HTML/SVG/JS не исполняются в главном окне. Незавершённые ответы остаются читаемым текстом, подсветка работает только для завершённых блоков.
- [ ] Длинный код и таблицы прокручиваются локально, длинные URL переносятся; текст ответа до 760 px. Таблицы имеют заголовки и доступное имя прокручиваемой области.
- [ ] Копирование блока передаёт исходный код; «Скопировано» появляется после реального успеха, отказ буфера доступен пользователю. Task list только для чтения.
- [ ] Ссылки используют разрешённый путь и согласованные протоколы приложения; удалённые изображения не загружаются молча. CSP не ослаблена.
- [ ] Модель и статус принадлежат ответу, usage/ID/контекст раскрываются в деталях; действия доступны при фокусе. Retry сохраняет отдельный смысл и предупреждение о повторном списании.
- [ ] Автопрокрутка работает только при чтении внизу; выше появляется «К новым сообщениям». Если история подгружается, видимое сообщение не меняет позицию.
- [ ] Обрыв, остановка и перезапуск сохраняют частичный текст и неизвестный расход; ветки и Retry не создают дублей. Запрет переключения бесед во время потока сохранён.
- [ ] На macOS проверены длинный Markdown, отказ clipboard, чтение выше потока, ветки и восстановление; прошли проверка типов и сборка, существующие потоковые тесты сохранены. Результаты внесены в журнал.
