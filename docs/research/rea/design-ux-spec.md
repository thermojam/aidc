# Design & UX Specification — AI Desktop Client

Дата: 11 ноября 2026. Статус: спецификация следующего редизайна, не отчёт о выполненной реализации.

## 0. Основания, допущения и UX-аудит

Цель: пользователь выбирает проект, понимает состав отправляемых данных, отправляет запрос и читает результат без конкуренции с настройками и диагностикой. Поверхность — **Operate** (выполнение задачи); содержимое ответа — Read.

Две трактовки запроса: косметически упростить текущий чат или перестроить рабочее пространство вокруг проектов. Принята вторая, с последовательным переносом уже существующих функций. Редизайн не расширяет полномочия приложения и не меняет критерии выпуска P0.

Проверяемый результат документа: каждому наблюдаемому недостатку соответствует место в новой компоновке, контракт состояний и критерий приёмки. Численные размеры ниже — проектные значения, а не измерения конкурентов.

### Источники и границы достоверности

- [Текущий экран](../../ref/aidc-chat.png): файл доступен в рабочей копии. Видны пустая история, перегруженный ввод, две красные ошибки, четыре нижних аккордеона.
- GPT/Codex-референс: основной ориентир композиции — док, навигация, спокойный центр, контекст и модель около ввода. Это не подтверждает доступность показанных моделей.
- Claude-референс: компактная строка ввода, инструменты внутри поля, метаданные рядом; глобальное ограничение аккаунта вынесено вверх. Последнее копировать только для действительно глобальных ограничений.
- [JetBrains-референс](../../ref/jet-chat.png): иерархия папка → сессии, ясный фокус поля, рабочая среда над вводом, модель под ним. Вкладки редактора, Git и IDE-панели не переносить без соответствующих функций.
- Код: `src/main.tsx`, `src/style.css`, `package.json`, `src-tauri/tauri.conf.json`; продуктовые ограничения: [spec.md](spec.md), результаты проверок: [checks.md](checks.md). В текущем коде уже есть проекты, несколько бесед и агентные срезы; ранние описания одного чата в `ui-refresh.md` устарели относительно этих частей.
- Сейчас React 19, обычный CSS и библиотеки Markdown уже установлены. Shadcn UI и Tailwind в `package.json` отсутствуют: это целевая компонентная база, требующая отдельного внедрения.
- `DESIGN.md` описывает прежнюю Int UI/Islands-систему. Ниже сохранены её смысловые роли; новые оттенки — предложенная эволюция. При реализации синхронизировать `DESIGN.md`, не создавать параллельную систему цветов.

Аудит выполнен по отрендеренным снимкам и статическому коду. Новое живое окно не запускалось; мышь, клавиатура, узкое окно, поток и восстановление после ошибки здесь не испытаны. Причина `transformCallback` не установлена. Оценки ниже относятся к видимому состоянию, а не ко всему приложению. Личные данные приложений-референсов не исследовались.

### Оценка A: когнитивная нагрузка

| Критерий | Результат по текущему снимку | Доказательство |
| --- | --- | --- |
| Единый фокус | Провал | Запись, захват, режим, файлы, каталог и ошибки конкурируют с текстом запроса |
| Чанкинг | Провал | Несколько самостоятельных сценариев собраны в одном большом блоке ввода |
| Группировка | Провал | Глобальная ошибка и локальные инструменты находятся в общей рамке |
| Иерархия | Провал | Красная диагностика заметнее недоступной отправки |
| По одному решению | Провал | Требуется одновременно понимать модель, режим, вложения и ошибку |
| Минимум выбора | Провал | Более четырёх самостоятельных действий около пустого поля |
| Рабочая память | Не установлено | Переход между экранами по снимку не проверяется |
| Прогрессивное раскрытие | Провал | Голос и захват со справочными текстами раскрыты до обращения к ним |

**7/8 критериев с наблюдаемыми провалами → критичная нагрузка в показанном состоянии.** Число четыре используется как ориентир группировки, а не универсальный запрет на длину меню.

### Оценка B: эвристики Нильсена

Шкала 0–4; Н/П — невозможно оценить по имеющемуся свидетельству. Среднее считается только по оценённым критериям.

| Эвристика | Балл | Основание |
| --- | --- | --- |
| Видимость статуса | 2 | Локальный режим и ошибка каталога видны; влияние на отправку не объяснено |
| Язык пользователя | 1 | `TypeError…transformCallback` показан как обычное сообщение |
| Свобода и контроль | Н/П | Escape, отмена и возврат требуют живого сценария |
| Консистентность | 2 | Плоские панели согласованы, инструменты представлены разнородными контролами |
| Предотвращение ошибок | Н/П | Проверка контекста есть, её поведение на снимке не установлено |
| Узнавание | 2 | Подписи действий понятны, проект выбирается через общий селектор |
| Эффективность | Н/П | Код палитры существует; runtime клавиатуры в тикете 13 остаётся открыт |
| Минимализм | 1 | Пустой чат уже показывает множество инструментов и четыре служебные секции |
| Восстановление | 1 | Техническая ошибка не предлагает понятного следующего действия |
| Контекстная помощь | 2 | Есть подписи о захвате и локальном режиме; ошибка без объяснения |

**Среднее 1,6/4 по семи оценённым эвристикам.** Это предварительная оценка статического состояния, не полноценный usability-тест.

### Находки по приоритетам

**P0:** по одному снимку блокирующий дефект не доказан. Ошибку каталога нельзя автоматически считать причиной отказа локального теста.

**P1:**

1. Техническое исключение без восстановления — красная строка на снимке; в коде общий `error` выводится под вводом и в настройках. Разделить ошибки по источнику, предложить действие, детали раскрывать отдельно.
2. Слишком много конкурирующих действий — на снимке голос, захват, модель, чекбокс и два вида вложений. Оставить основной ввод, компактные метаданные и меню добавления.
3. Рабочая область зависит от нижних служебных секций — четыре аккордеона под вводом. Перенести расписания и генерацию в отдельные представления; ход текущей задачи показывать у её ответа.

**P2:** дерево проектов заменить вместо общего селектора; недоступный голос объяснять внутри меню инструмента; пустую историю отличать от пустой поисковой выдачи.

**P3:** унифицировать размеры контролов, фокус, подписи и ритм отступов.

Что работает: плоские поверхности без декора; явная подпись «Локальный тест · без сети»; настройки уже вынесены вниз навигации. Сохранить эти принципы.

## 1. Концепция и архитектура интерфейса

### 1.1. Сетка

```text
Нативная полоса окна / интегрированный titlebar
┌──────┬────────────────────┬──────────────────────────────────┐
│ Док  │ Поиск / Новый чат  │ Заголовок беседы · проект · меню │
│ 48px │                    ├──────────────────────────────────┤
│      │ Группы и проекты   │ История / выбранное представление│
│      │ Вложенные беседы   │                                  │
│      │ Недавние           │                                  │
│      │                    ├──────────────────────────────────┤
│ ⚙    │                    │ Контекст · Ввод · Модель · Отправить│
└──────┴────────────────────┴──────────────────────────────────┘
```

Три постоянные области: док, выдвижная навигация, рабочая область. Artifact — дополнительная область по запросу, а не четвёртая постоянная панель.

- Док 48 px, кнопки 36×36, иконки 18–20 px. Сверху «Беседы», далее «Задачи», «Генерация» только для доступных функций; настройки снизу. Tooltip с названием и сочетанием, доступное имя независимо от tooltip. Активность обозначать подложкой и маркером, не одним цветом.
- Навигация 264 px, изменение ширины в пределах 220–320 px; заголовок 48 px, строка сущности 32 px. Верх: новый чат и поиск. Низ: только локальные действия навигации, без дублирования настроек дока.
- Основная область: `min-width: 0; min-height: 0`. Шапка 48 px, история `minmax(0, 1fr)`, composer в отдельной строке `auto`. Не закреплять ввод поверх сообщений через абсолютное позиционирование.
- История и composer: `width: min(100% - 48px, 800px)`. Текст ответа до 760 px. На узком окне боковые отступы 16 px. Отсутствуют внешние карточки вокруг каждой панели.
- История и навигация прокручиваются независимо. Body не прокручивается. Длинный код прокручивается внутри блока, не расширяет окно.

### 1.2. Проекты и группы

Проект — именованное рабочее пространство с явно подключёнными материалами и беседами. Выбор проекта не даёт автоматического доступа к папке и не означает отправку всех файлов.

| Раздел | Смысл | Представление |
| --- | --- | --- |
| Product | Пользовательская группа продуктовых проектов | Заголовок группы, внутри обычные проекты |
| Information | Пользовательская группа исследовательских проектов | Аналогичная структура, не отдельный тип облачного подключения |
| Проекты | Остальные неархивные проекты | Папка, имя, кнопка раскрытия, беседы внутри |
| Недавние | До 10 последних бесед из всех проектов | Ссылка на ту же беседу, не её копия |

Product и Information взяты из визуального референса как пример пользовательских групп. Не создавать пустые фиктивные разделы. Пока произвольные группы не поддержаны данными, выпускать «Проекты» и «Недавние»; добавление групп — отдельная задача модели данных, не CSS-имитация.

Стандартные значки: Folder — проект, MessageSquare — беседа, FileText — файл, Image — изображение, Clock — расписание, Globe — реально подключённый веб-источник. Terminal запрещён как декоративная иконка проекта, если команды недоступны. Пользовательский значок проекта — необязательный, один из ограниченного набора; цвет не кодирует права.

Один проект располагается только в одной группе. Недавняя беседа может повторяться ссылкой; выделяется по ID. Сохранить состояния раскрытия и ширину локально. Название обрезать одной строкой; полное доступно при фокусе и в меню. Контекстное меню и кнопка «…» предлагают одинаковые действия. Удаление/архивация не запускаются через неочевидную иконку.

Иерархия максимум проект → беседа; материалы проекта открываются отдельным представлением. Для настоящего дерева файлов нужны отдельные права и состояние загрузки. Пустой список: «Пока нет бесед» + «Новый чат»; «Ничего не найдено» только при непустом поиске.

### 1.3. Адаптивность

| Ширина окна в CSS px | Правило |
| --- | --- |
| ≥1200 | Док + навигация открыты по умолчанию; ручное скрытие сохраняется |
| 960–1199 | Док виден, навигация первоначально свёрнута; можно открыть, если центр остаётся ≥560 px |
| 640–959 | Док виден; навигация открывается modal Sheet поверх центра, закрывается после выбора |
| <640 | Док скрыт; кнопка навигации в шапке; один рабочий экран |

Автоматическое сворачивание из-за ширины не перезаписывает пользовательское предпочтение широкого окна. При открытии Sheet фокус внутри, Escape закрывает, возврат на кнопку. При 200% масштабе применяются те же правила доступной ширины.

Artifact рядом только если после дока и навигации остаются ≥560 px чату и ≥360 px Artifact. Иначе — замена центра с кнопкой «Назад к беседе»; черновик, позиция чтения и поток сохраняются. На высоте <700 px composer ограничить 35% доступной высоты; редкие параметры только в popover.

## 2. Smart Prompt — умный ввод

### 2.1. Структура и размеры

Один непрозрачный блок без тени, радиус 12 px, граница 1 px. Внутренние отступы 12–16 px. Не создавать плавающую карточку поверх последнего ответа.

1. Строка контекста: `[Проект ▾] [Этот компьютер]`; появляется только если эти значения полезны текущему сценарию. «Этот компьютер» означает место хранения/работы, а не локальное исполнение облачной модели. В подробностях явно: «Ответ через SimpleClaw; выбранные материалы отправятся провайдеру».
2. Чипы выбранных материалов: имя, тип, размер, удаление. До двух строк, далее «Ещё N». Доступен полный список с предпросмотром. Ошибка файла показана у этого файла.
3. Настоящий `textarea`: минимум 2 строки, автоподстройка до 8 строк или 240 px, затем внутренняя прокрутка. Видимая/доступная метка «Сообщение», placeholder не заменяет label. Текущий лимит 2000 символов не повышать оформлением; счётчик показывать с 80% лимита.
4. Нижняя строка: слева «+» и модель; справа текстовая кнопка «Проверить контекст», затем «Отправить». Во время запроса на её месте «Остановить». Для платных действий сохранить текстовые подписи.

В обычном пустом состоянии нет раскрытых полей голоса, захвата, чекбокса агента, тарифа и технической диагностики. Модель и проект остаются видимыми.

### 2.2. Инструменты ввода

«+» открывает DropdownMenu: «Прикрепить файл», «Прикрепить изображение», «Записать голос», «Снимок окна…». Поддержку определять текущими возможностями, не названием модели. Неподдержанный пункт отключён с объяснением; если функция вообще не реализована — отсутствует.

Микрофон допустим как дополнительная кнопка 32×32 внутри ввода при доступном распознавании. Не дублировать две постоянно видимые кнопки одного действия. Захват остаётся в «+», поскольку используется реже.

Голос: запрос разрешения ОС → запись с таймером, «Остановить»/«Отменить» → подтверждение стоимости распознавания → редактируемый текст → явное добавление в черновик. Запись не отправляет запрос модели автоматически. Ошибка разрешения предлагает инструкцию настройки ОС; аудио и текст не теряются молча.

Захват: системный выбор окна → предпросмотр → «Прикрепить» или «Отменить». Отмена не является ошибкой. Отказ разрешения объяснить рядом с инструментом. Захват никогда не прикрепляется автоматически и не отправляется без проверки контекста.

### 2.3. Модель, режим, расход

Кнопка модели открывает Popover с поиском и категориями. Строка содержит реальное `display_name`, провайдера, доступность; избранные первыми. «GPT-6 Sol Среднее» и «Opus 5.5 High» — лишь надписи на референсах, не зашитые модели клиента.

Уровень рассуждения показывать отдельным параметром только при подтверждённой поддержке API. Не имитировать High/Auto изменением подписи. Агентный режим перенести из чекбокса в явный переключатель «Чат / Агент» внутри параметров запроса; активный агент отображается постоянным чипом. Выбор агента не включает инструменты, команды или доступ к файлам без действующего контракта.

Статус под нижней строкой занимает максимум одну строку в норме: «Локальный тест · без сети» или «SimpleClaw · потребуется подтверждение стоимости». Во время ошибки допустимо увеличение высоты ради понятного восстановления.

Токены: измеренные сервером показывать как usage ответа; локальную оценку помечать «≈». Если размер окна контекста неизвестен, текст «Лимит контекста неизвестен», без процентного кольца и ложного «0%». Отсутствие usage = «Расход неизвестен», не ноль. Не использовать зелёный индикатор для неподтверждённой доступности сети: успешный каталог не доказывает готовность платного POST.

### 2.4. Проверка и отправка

Путь: черновик → проверка состава → просмотр файлов/ветки/модели/оценки → подтверждение → отправка. Не удалять существующую обязательную проверку ради визуальной простоты. Любое изменение текста, файлов, проекта, режима, модели, параметров или ветки сбрасывает подтверждение. Вызов проверяется Rust, не только disabled-кнопкой.

При потоке сохранять введённый следующий черновик; не отправлять его автоматически в очередь. Кнопка остановки доступна. Частичный ответ остаётся в истории. Повтор — отдельное действие с предупреждением о возможном повторном списании; неизвестный исход не допускает автоматического повтора POST.

Enter отправляет только при готовом подтверждённом состоянии; Shift+Enter добавляет строку. Если проверка не выполнена, Enter не отправляет и переводит к «Проверить контекст» с пояснением. Не перехватывать Enter во время IME-композиции или открытого списка подсказок.

### 2.5. @mentions и /commands

- `@` после пробела или в начале открывает список явно доступных материалов текущего проекта; имя + путь относительно проекта + тип. Вне проекта — только уже выбранные вложения. Нет скрытого обхода диска.
- `@агент` появляется лишь при реестре доступных агентов. Выбор не даёт новых полномочий. Для первого среза без такого реестра раздел отсутствует.
- `/` в начале строки открывает существующие команды приложения: новый чат, поиск, проверка контекста. Это UI-действия, не shell-команды. Разрушительные и платные команды требуют своих подтверждений.
- Список до 8 видимых строк, прокрутка, фильтр по вводу; стрелки выбирают, Enter вставляет/активирует, Escape закрывает без удаления текста, Tab принимает выбранную подсказку. Активный пункт объявляется через `aria-activedescendant`, список имеет семантику listbox.
- Если подходящих результатов нет — «Нет доступных материалов» и «Выбрать файл…». Обычный email не преобразуется в mention без явного выбора.
- Для первого внедрения сохранить textarea: выбранный ресурс хранить отдельным чипом и ID, текстовая ссылка — только представление. Удаление чипа убирает ресурс из контекста. Не вводить сложный rich-text редактор ради плашек внутри строки.

## 3. Статусы, диагностика и ошибки

### 3.1. Маршрутизация

| Событие | Место | Текст / действие |
| --- | --- | --- |
| Локальный mock | Спокойный Badge у модели | «Локальный тест · без сети» |
| Каталог не обновлён, кэш есть | Badge у модели + подробности | «Каталог устарел» → дата, «Обновить» |
| Каталога нет | Inline Alert у выбора модели | «Не удалось загрузить модели» → «Обновить»; локальный тест остаётся доступным |
| Нет ключа / 401 | Alert у отправки | «Подключите API-ключ» / «Ключ не принят» → настройки подключения |
| Файл недоступен | Чип файла | Причина, «Выбрать заново» / «Удалить» |
| Обрыв ответа | У конкретного ответа | «Ответ прерван. Частичный текст сохранён. Расход неизвестен» |
| Ошибка резервной копии | В панели данных + toast | «Не удалось создать копию» → подробности, доступный повтор операции |
| Сбой отображения ответа | На месте ответа | «Не удалось показать ответ» → «Показать текст», диагностика |
| Сбой всего рабочего экрана | Error boundary | «Не удалось открыть рабочую область» → «Открыть заново», без удаления данных |

Состояние привязывается к операции/ID попытки, а не одной общей строке `error`. Обновление каталога не стирает ошибку генерации; переключение беседы не переносит её ошибку в другую беседу. Поздний ответ старой операции не меняет текущую модель/беседу.

### 3.2. Toast

Использовать Sonner. Уведомления справа сверху, ниже titlebar, максимум три; одинаковые события объединять по операции. Успех — 4 секунды, фоновые предупреждения — 8 секунд, критические — до закрытия. При hover/фокусе таймер остановлен; пользователь может закрыть уведомление. Toast не захватывает фокус.

Критическая ошибка имеет toast для привлечения внимания **и постоянное сообщение в месте исправления**. Toast не единственный носитель ошибки, расхода или потери данных. Не показывать toast для каждой SSE-дельты, обычной остановки, отмены системного picker и постоянного mock-режима. Системное уведомление ОС не дублирует каждую ошибку внутри активного окна.

`role=status`/polite для фоновых изменений; `role=alert` только для нового блокирующего состояния. Не объявлять весь поток ответа заново экранному диктору.

### 3.3. Технические подробности

Пользовательский текст отвечает на три вопроса: что не получилось, что сохранено/неизвестно, что сделать дальше. Пример: «Не удалось обновить каталог. Доступен список от 10 ноября. Попробуйте обновить позже».

«Технические подробности» открывают Dialog: время, операция, код, HTTP-статус, request ID, очищенное сообщение; копирование только этого безопасного набора. Никаких ключей, тела запроса, содержимого файлов, полного локального пути и стеков с пользовательскими данными по умолчанию. Случайный TypeError не переименовывать в «Сеть недоступна» без основания.

Журнал диагностик — в настройках, не нижний аккордеон чата. Пока нет постоянного журнала, достаточно подробностей конкретной операции; не добавлять сервис логирования ради редизайна.

### 4.3. Markdown и история

- `react-markdown` + `remark-gfm`; HTML в ответах не выполнять, `skipHtml` явно. Не добавлять `rehype-raw` ради визуального совпадения. Ссылки и изображения обрабатываются отдельными контролируемыми renderer-компонентами.
- Абзацы с интервалом 12 px, заголовки h2 20/28 и h3 17/24, без громадного h1 внутри ответа. Списки сохраняют вложенность и маркеры; длинные URL переносятся.
- Fenced code: фон field, шапка с языком и «Скопировать», горизонтальная прокрутка, без автоматических номеров строк. Копировать исходный код без HTML-разметки; показывать «Скопировано» только после успеха clipboard. При отказе — доступное сообщение ошибки.
- `highlight.js` применять к завершённым блокам, не переподсвечивать каждую дельту всего ответа. Незавершённый fence показывать текстом без мерцания. Строки HTML/SVG/JS не становятся DOM основного окна. DOMPurify применять к действительно создаваемому HTML на границе, а не как замену изоляции исполнения.
- GFM-таблицы: `table` с заголовками, обёртка с горизонтальной прокруткой и доступным именем; таблица не расширяет чат. Cell padding 8×12, заголовки semibold, без тяжёлой сетки.
- Task list: read-only checkbox с доступным состоянием; пользовательский клик не меняет ответ и не запускает задачу.
- Внешние ссылки открывать через разрешённый путь приложения, разрешать только согласованные протоколы. Удалённые изображения не загружать молча; показывать заглушку/явное действие согласно политике сети. Не обходить CSP ради Markdown.
- Модель и статус принадлежат ответу; usage, ID, состав контекста — в «Детали ответа». Действия копирования/ветвления доступны при focus-within, а не только hover. Retry не заменять «Продолжить».
- Поток прокручивает вниз только если пользователь уже внизу. При чтении выше показать «К новым сообщениям»; не перехватывать прокрутку. Разделитель загрузки истории не меняет положение видимого сообщения.

## 5. Десктопный UX — Tauri v2

### 5.1. Окно и titlebar

Простейший первый этап — сохранить нативные декорации и встроить шапку приложения под ними. Кастомный titlebar — отдельный визуальный срез, поскольку затрагивает drag, resize, fullscreen и доступность.

macOS: при интеграции titlebar сохранить нативные traffic lights, безопасное место слева не менее 80 px; точные отступы проверить в фактическом окне. Не рисовать красные/жёлтые/зелёные DOM-кружки поверх нативных кнопок. Предусмотреть состояние fullscreen и неактивного окна.

Windows: предпочтительны нативные системные controls. Если используется `decorations: false`, нужны реальные действия minimize/maximize/restore/close, корректный resize и отдельная приёмка Snap Layouts. Иконки крестика не доказывают нативную совместимость. Высота полосы около 36 px — стартовое значение, масштаб DPI проверять отдельно.

Drag-region только на свободных участках titlebar, не на селекторах, кнопках, полях и вкладках. Проверить двойной клик, перетаскивание из неактивного окна и смену монитора. Разрешения оконных команд выдавать поимённо только `main`, не viewer. Особенности конфигурации titlebar зависят от платформы: [Tauri Window Configuration](https://v2.tauri.app/reference/config/).

Закрытие при потоке не создаёт повторного POST. Поведение остановки и восстановления согласовать с существующим Rust-контрактом. Если ОС закрывает процесс до завершения, при следующем запуске показать прерванную попытку и сохранённый частичный ответ.

### 5.2. Drag-and-drop

Использовать события Tauri `onDragDropEvent` существующего webview; не включать одновременно независимую HTML- и Tauri-загрузку, создающую дубли. Подписку освобождать при unmount. Контракт событий: [официальный Webview API](https://v2.tauri.app/reference/javascript/api/namespacewebview/).

При входе файлов показать рамку и текст «Добавить файлы в сообщение» над областью чата; drop не отправляет запрос. Дроп в навигацию не перемещает и не удаляет файлы. Папка требует отдельного подтверждения и предварительного списка в поддержанном срезе; иначе объяснить, что следует выбрать отдельные файлы.

Чтение, проверку пути, кодировки, размера и секретных имён выполняет Rust. UI показывает `loading → ready / rejected`; неподдержанные файлы перечисляются поимённо с причиной. Drop и picker используют одну валидацию. Дубликаты определять по существующему контракту идентичности вложения, не только имени. Ни drop, ни mentions не предоставляют произвольный доступ к диску.

### 5.3. Клавиатура и доступность

Сохранить действующие сочетания палитры; при конфликте предложенных ниже выбрать одно и показать его в tooltip/палитре. Базовый набор: Cmd/Ctrl+K — палитра, Cmd/Ctrl+N — новая беседа, Cmd/Ctrl+B — навигация, Cmd/Ctrl+, — настройки. Не перехватывать обычный ввод и нативное копирование.

Escape сначала закрывает верхний popover/dialog; не останавливает платный запрос неочевидно. Остановка — явная кнопка. После закрытия поверхности вернуть фокус; после выбора беседы — в заголовок/историю без автоматической отправки. Новая беседа фокусирует textarea. Drag-разделитель ширины доступен стрелками и имеет separator-семантику.

Видимый focus ring 2 px с отступом 2 px; действия не зависят от hover. Поддержать reduced motion; только короткие переходы 100–150 ms для раскрытия, без анимации текста ответа. Информация не кодируется одним цветом.

После реализации: `npm run typecheck`, `npm run build`; `cargo test` при изменениях Rust/IPC. Линтер сейчас не настроен. Сборка не заменяет визуальную и клавиатурную приёмку. Для потоков сохранить существующие тесты разрезанного UTF-8/JSON, нескольких событий, отмены и восстановления; переделка UI не повод менять их контракт.

**Для этого документа выполнено:** просмотр четырёх PNG, сверка ключевых участков кода, зависимостей, текущих документов и блокирующих тикетов. **Не выполнено:** живой UX-прогон, измерение контраста готового экрана, тесты приложения, сборка, Windows. Реализация не менялась.
