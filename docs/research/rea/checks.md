Статусы относятся к **доказательствам**, а не к готовности приложения. «Подтверждено» означает только указанный источник и границу проверки.

## Реализация и проверки локального среза — 4 ноября 2026

- **Сделано:** Tauri 2.12.5, Rust 1.99.1, React/TypeScript, SQLite (`rusqlite` 0.37.0). Три команды ограничены окном `main` через `AppManifest::commands` и capability. `start_mock_generation` не обращается к сети и не использует ключ.
- **macOS 27.2 arm64, приложение запущено:** `.app` открылся; сообщение `Тест macOS` дало поток частичных дельт и ровно один полный ответ; длинный поток остановлен, частичный текст получил статус `stopped`; после закрытия и запуска история обоих ответов восстановилась. При `killall -9 ai-desktop-client` во время третьего потока после повторного запуска сохранился частичный ответ со статусом `interrupted`.
- **Граница IPC на macOS:** отдельная тестовая сборка открыла `viewer.html` в окне `viewer` без capability. Все три вызова (`list_history`, `start_mock_generation`, `stop_generation`) отклонены; запрос `viewer must fail` не появился в SQLite (проверен счётчик `0`). Это проверка окна viewer, не изоляции интерактивного HTML/iframe.
- **Автоматические проверки на macOS:** `cargo test -q` — 4 теста прошли: разрезанный UTF-8/JSON, несколько событий, EOF без `[DONE]` с сохранением частичного текста и последовательности, отмена, перевод незавершённой попытки в `interrupted` при повторной инициализации БД. `npm run build` — проверка TypeScript и Vite прошли. `tauri build --bundles app` — `.app` собран. Линтер не запускался: в проекте пока нет его конфигурации.
- **Открыто на этапе исходного среза:** количественный предел потери последнего пакета при аварии не измерен; тогда миграция дерева и backup ещё не входили в узкую схему. Текущее состояние A3–A4 описано ниже. Windows 10/11 x64 не запускалась. [Сценарий Windows](smoke-windows.md) подготовлен. Нет проверки реального SimpleClaw SSE, денег и Artifacts.

## Подготовка A3–A4 — 4 ноября 2026

Rust 1.99.1 установлен во временный каталог для локальных проверок. Далее нужны: для A3 — вызов узких команд из запущенного главного окна и отказ из `viewer`; для A4 — проверка веток и Retry в запущенном приложении, неизменность выбранных вложений и запуск приложения с миграцией. Копирование БД через SQLite Backup API уже прошло отдельный тест; восстановление копии в приложении ещё открыто.

**Локальные проверки A3–A4, macOS, 4 ноября 2026:** во временной отдельной связке Keychain синтетический ключ записан, прочитан, заменён и удалён; связка удалена после опыта. Это проверка системного API через `security`. Логика новых Rust-команд прошла тест сохранения, замены, проверки статуса и удаления на синтетическом секрете с mock-хранилищем; нативный вызов этих команд ещё не проверен. На синтетической файловой копии старой схемы выполнена SQL-миграция `user_version=0 → 1`: четыре сообщения, две попытки, цепочка родителей, `last_seq` и частичный текст сохранены; `foreign_key_check` и `integrity_check` без ошибок. После повторного открытия незавершённый ответ стал `interrupted`. Тест SQLite Backup API подтвердил открытие копии с частичным ответом; код также сверяет количество сообщений, общий объём текста, число попыток и версию схемы. `cargo test --offline` с Rust 1.99.1 прошёл: 7 тестов. `npm run build` и тестовая `.app` сборка прошли. Тестовое приложение с отдельным идентификатором запущено и создало отдельную SQLite-базу, но состояние окна viewer инструментом UI прочитать не удалось, поэтому отказ новых команд не засчитан. Запуск приложения с миграцией, ветки, Retry, вложения и Windows остаются открытыми.

**Следующий срез A3–A4, macOS, 4 ноября 2026:** Rust-тест `keyring` записал, заменил и удалил синтетический ключ в нативном Keychain вне песочницы. В песочнице запись отклоняется с `-60008`; поэтому тест помечен как требующий отдельного запуска и выполнен с `--ignored`. Файловая SQLite-база со старой схемой мигрировала при `init_db` и повторно открылась с сохранёнными `parent_id`, `last_seq` и частичным ответом `interrupted`. Тест Retry подтвердил соседний ответ, новую попытку, сохранение прежнего текста и продолжение выбранной старой ветки. `cargo test --offline`: 9 обычных тестов прошли, 1 нативный Keychain-тест пропущен; отдельный запуск этого теста прошёл. `npm run build` и тестовая macOS `.app` сборка прошли. Сборка запущена в отдельном профиле, но инструмент UI не смог привязаться к её окну; отказ девяти команд viewer и кнопки веток/Retry в работающем окне не засчитаны. Windows снята с текущего приоритета, остаётся непроверенной.

**Правки после ревью среза:** запись Keychain привязана к идентификатору сборки, поэтому тестовая `.ipc-test` не использует запись обычного приложения. Viewer засчитывает только отказ по правам, а не любую ошибку команды. Выбор ветки держит блокировку до обновления БД; список всех ответов в UI даёт вернуться к скрытым продолжениям. Завершение статусов сообщения и попытки теперь транзакционное, тест с искусственной ошибкой второго обновления проверяет откат первого. Эти правки пока проверены Rust-тестами и сборкой, отрицательный runtime-тест viewer остаётся открытым.

**Проверка SimpleClaw на macOS, 4 ноября 2026:** публичный `GET /v1/models` вернул HTTP 200 и 40 записей. Из каталога перед запросом выбрана модель `gpt-oss-20b` с опубликованной ценой 6,6 ₽/млн входных и 33 ₽/млн выходных токенов. Пользователь разрешил суммарный расход до 100 ₽ на два тестовых ключа. По одному короткому `POST /v1/chat/completions` с `max_tokens=16` отправлено каждым ключом, без автоматических повторов; оба вернули HTTP 503, код `UPSTREAM_USAGE_UNCERTAIN` и сообщение провайдера о возврате резерва. Успешный ответ, `usage`, фактическое списание и SSE этим опытом не подтверждены. Повторы после неизвестного результата не выполнялись. Значения ключей не выводились и не сохранялись в репозитории.

2. Проверены `Info.plist` трёх пакетов: Claude, ChatGPT/Codex, CodexBar; проверен поиск Cursor в обычных каталогах приложений и Spotlight.
3. REA выполнил статический анализ Claude с `detail=summary`; точечные просмотры двух модулей и трасса приведены в `evidence.md`. Результат неполный по семантике; нет наблюдения исполнения.
4. REA для Codex: первый вызов обнаружил расхождение контрольной суммы распакованного нативного файла; повтор с `record-and-continue` превысил 300 с. Инвентаризация пакета сохранилась, но результат превысил лимит передачи. Адресно прочитан заголовок ASAR; повторять полный анализ без изменения метода не нужно.
5. Просмотрены официальные страницы SimpleClaw, Tauri, Electron, HTML и SQLite. Платные POST, доступ к личному аккаунту и чтение чужих чатов не выполнялись.
6. Подготовлены решения для следующей стадии. Код приложения, тесты Rust/React и установщики отсутствуют; запускать `test`, `lint` или `build` пока нечего.

## Вопросы к SimpleClaw перед обещанием надёжного Retry

1. Какое точное терминальное SSE-событие завершает успешный `chat/completions` и всегда ли оно содержит `usage` и серверный ID?
2. Какие коды/события означают, что запрос был принят, но результат или списание неизвестны клиенту?
3. Поддерживается ли идемпотентный ключ для POST, безопасное повторное чтение результата или возобновление по `Last-Event-ID`? Если да, сроки хранения и точные условия.
4. Что происходит при закрытии TCP-соединения и отмене во время генерации: прекращается ли upstream и как учитывается расход?
5. Есть ли авторизованный бесплатный метод проверки Bearer-ключа и методы получения баланса/расхода по этому ключу?
6. Где получать проверенные лимиты контекста, токенизатор и возможности каждой модели, а также версию/время действия тарифов?

Пока ответов нет, продукт использует осторожную политику `spec.md`. Это не блокирует разработку локального вертикального среза, но запрещает обещать клиенту безопасный автоматический повтор и точную стоимость при обрыве.
