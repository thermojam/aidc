# Уточнённое ТЗ для следующей стадии

Статус: проектное решение по итогам доступных свидетельств; раздел «Локальный вертикальный срез» описывает уже реализованную часть. Остальные требования не означают готовность клиента. Заменяет спорные части исходного ТЗ. Цель первого релиза — локальный чат с ключом пользователя, текстовыми файлами, ветками и безопасным просмотром результатов. Собственного сервера нет.

## 1. Граница первого релиза

**P0:** Windows 10/11 x64 и macOS Apple Silicon; Intel macOS включать только после проверки на реальной машине. Ключ в системном хранилище, каталог моделей, один активный запрос на чат, поток текста, Markdown без HTML, подсветка завершённых блоков кода, локальная история с ветками, явное подключение отдельных текстовых файлов, панель Artifacts с Code и экспортом. Статический Preview для HTML/SVG — обязательный безопасный минимум. Интерактивный автономный HTML/CSS/JS допускается в P0 только после проверок из раздела 8; иначе поставляется статический Preview с ясной надписью «Интерактивный просмотр недоступен». Это не скрытая замена функции: режим исполнения явно виден в интерфейсе и критериях приёмки.

**P1:** React preview, внешние зависимости, проектное дерево, индексирование, изображения, расширенный справочник моделей, статистика расходов и импорт/экспорт. **P2:** агентные инструменты, редактирование файлов, команды, Git и дополнительная синхронизация. Никакой скрытой платной суммаризации или проверки ключа платным запросом.

Ключевой путь: установка → сохранить ключ → выбрать модель → отправить текст → видеть поток → получить подтверждённое завершение или частичный ответ → открыть историю → прикрепить явно выбранный файл → открыть Artifact как код или безопасный preview.

## 2. Стек и границы доверия

Предварительный выбор: Tauri 2, Rust, React/TypeScript, SQLite. Это гипотеза для вертикального среза, не победа по вымышленному размеру или скорости. Rust владеет HTTPS, ключом, составом запроса, состоянием генерации, файловым доступом и БД. React показывает состояние и посылает только узкие команды. SQLite доступна только Rust. Не нужен отдельный Zustand, Tailwind или набор компонентов до появления реальной потребности; начать с локального состояния React и простых стилей.

Сравнение: Tauri использует системные WebView2/WebKit, поэтому меньше собственных компонентов браузера в поставке, но две разные реализации требуют испытаний и усложняют безопасный HTML preview. Electron поставляет Chromium и даёт более одинаковую среду, отдельную сессию/процесс и MessagePorts; цена — сопровождение обновлений Chromium, упаковки и полномочий Node. Ни один стек не устраняет опасность недоверенного HTML автоматически. Если доказать изоляцию интерактивного preview на Tauri не получится, первый релиз остаётся со статическим preview; переход на Electron требует отдельного решения после одинаковых тестов на обеих ОС.

Ключ: выбрать проверяемую библиотеку системного хранилища после короткого прототипа. На macOS — Keychain; на Windows — Credential Manager через нативный слой. В JS нет `get_api_key`, ключ не пишется в БД, настройки и логи. Команды: `save_key`, `delete_key`, `key_status`, `list_models`, `start_generation`, `stop_generation`, операции с чатами и выбранными файлами. `start_generation` принимает ID модели и ID сохранённых узлов/вложений, а не произвольный URL или полный текст чужого файла. Rust проверяет происхождение окна, валидирует состав запроса и ограничивает частоту/одновременность; компрометация основного окна всё ещё может злоупотребить разрешённой отправкой. Поэтому нужны тесты не только на чтение ключа, но и на отправку от имени недоверенного окна.

Для Tauri собственные команды включить в `AppManifest::commands` и разрешить поимённо только главному окну. Не использовать `windows: ["*"]` или неявно включённые capability. Плагинам оставить минимум. После сборки выполнить отрицательные проверки вызовов из viewer. Политика содержимого основного окна запрещает удалённые скрипты.

## 3. SimpleClaw, модели и деньги

Фиксированный адрес `https://simple-claw.ru/v1` в P0. Только HTTPS, системная проверка сертификата, без переноса `Authorization` при redirect на иной origin. Rust посылает `GET /models` без секрета и `POST /chat/completions` с Bearer. Для P0 — текстовые сообщения. Максимальный размер JSON, файлов и ответа задать в конфигурации продукта после проверки реальных нагрузок; неконтролируемый поток ограничивать по времени простоя и суммарному объёму.

Каталог хранить с меткой времени и версией снимка: показывать последний успешный результат сразу, обновлять в фоне, запрос с таймаутом, ответ устаревшей попытки обновления не должен перезаписать новый. Ошибка сети оставляет кэш с пометкой времени. Выбор модели фиксируется в `generation_attempts` до отправки. Смена выбора во время потока действует только на следующий запрос. `GET /models` не проверяет ключ; статус «ключ сохранён», а не «подключено». Проверка ключа — только документированный бесплатный авторизованный маршрут, если он появится; иначе результат первого явно отправленного пользователем запроса.

`pricing` брать из свежего каталога SimpleClaw и хранить снимок цены для попытки. Показать дату цены; предварительный расход — оценка, подтверждённый usage — токены сервера, реальное списание — только если сервер предоставляет финансовый показатель. Баланс без документированного Bearer-маршрута не показывать. Модели без подтверждённой цены, лимита и свойств остаются в «Остальные»; цена и предел контекста «неизвестны». Категории «Мышление / Скорость / Экономия» — версия локального справочника с источником и датой, плюс пользовательские правки. По имени нельзя выводить поддержку vision, инструментов или reasoning. Неизвестная модель доступна для ручного выбора после предупреждения, если серверный каталог её содержит; нельзя обещать, что она примет запрос.

Голосовой ввод — отдельный путь P1: только явная кнопка запрашивает микрофон и начинает запись; пользователь останавливает её сам (жёсткий предел 10 минут и 25 МиБ). Аудио не сохраняется в SQLite и отправляется в SimpleClaw только после второго явного действия с показом модели, тарифа и оценкой расхода. Перед POST Rust обновляет публичный каталог и сверяет текущий протокол и тариф; неизвестная или изменившаяся цена блокирует запрос. После неопределённого исхода тот же фрагмент записи автоматически не повторяется. Транскрипт показывается редактируемым и попадает в сообщение только по отдельной кнопке; отправка в чат остаётся обычным действием.

Снимок окна на macOS — отдельное явное действие: системный интерактивный селектор `screencapture` получает конкретное окно и разрешение TCC macOS. Снимок сначала возвращается только для локального предпросмотра; исходник хранится временно для выбора, затем временный файл сразу удаляется. Только кнопка «Прикрепить снимок» переносит PNG в обычные черновые вложения. Отказ очищает предпросмотр; до прикрепления снимок не включается в контекст, не пишется в SQLite и не передаётся модели. Нет фонового или повторного захвата. Текущая реализация ограничена macOS; поддержка Windows требует отдельного системного сценария.

Справочник ограничений контекста и совместимых токенизаторов отделить от динамического каталога. Если нет проверенного предела, отключить обещание «помещается точно», применить консервативное ограничение размера и предупреждение. Считать токены точно только для подтверждённой пары модель/токенизатор; иначе показывать приблизительную оценку. Для обязательной части без известного безопасного бюджета — блокировать отправку с объяснением или позволять явный пользовательский риск только в рамках лимита локального размера; не утверждать гарантии отсутствия переполнения.

HTTP-ошибку отображать по `error.code`, HTTP-статусу и безопасному `requestId`. `429` не сводить к «слишком много запросов»: есть отдельные рублёвые и токеновые лимиты. Технический лог не содержит ключ, полный prompt и текст ответа.

Контролируемая проверка 4 ноября 2026 года дала `503 UPSTREAM_USAGE_UNCERTAIN` на двух отдельных коротких запросах. До подтверждения `usage` и финансового результата клиент показывает неизвестный расход и не повторяет POST автоматически. Сообщение сервера о возврате резерва не заменяет подтверждение фактического списания. Подробности опыта — в `checks.md`.

## 4. Поток и повтор

Парсер SSE в Rust собирает UTF-8 и строки независимо от TCP-чанков, допускает несколько событий в чанке и многострочный `data`, обрабатывает пустые дельты, JSON-ошибку и документированное терминальное событие. `EOF` без подтверждённого завершения — `interrupted`, даже если уже пришёл `finish_reason`; точное правило завершения уточнить по контракту SimpleClaw. Отсутствие `usage` — «неизвестно», не ноль. Остановка чтения — «остановлено локально», без обещания отмены расходов.

Каждый запрос: неизменяемый снимок модели, параметров, списка узлов, версий файлов и системных инструкций; локальный `attempt_id`; порядковый `seq` для каждого события; серверные ID ответа/запроса, если получены. Состояния: `prepared`, `sending`, `streaming`, `completed`, `interrupted`, `stopped`, `failed`. Сохранять частичный текст пакетами и при закрытии. UI получает через Tauri Channel только дельту с `attempt_id`/`seq` и отдельный итог; не передавать растущую строку на каждый токен. Собирать UI-обновления по кадру или короткому интервалу; ограничить очередь, при переполнении дать UI восстановить актуальный сохранённый снимок, не теряя порядок. Во время потока показывать лёгкий текст; Markdown/подсветку разбирать в фоне и окончательно после завершения.

Автоповтор допускается только если клиент доказал, что байты POST не отправлялись. Ошибка до первого токена не является таким доказательством. Во всех сомнительных случаях только явная кнопка Retry с предупреждением о возможном повторном списании. Retry создаёт новую попытку от того же пользовательского узла и не добавляет оборванный ответ в контекст. «Продолжить ответ» — отдельный новый платный запрос, где частичный ответ добавлен явно; подписать это действие. Серверное возобновление потока разрешить лишь после документированного и испытанного контракта SimpleClaw. Никакого автоматического повторения вслед за reconnect.

Агентный режим включается пользователем отдельно и доступен только для `gpt-oss-20b`, единственной модели с проверенным function calling. В нём доступны локальный калькулятор и, когда у беседы выбрана папка проекта, поиск по поддерживаемым текстовым файлам первого уровня. Поиск ограничен 500 элементами и 1 МиБ суммарно, каждый файл — до 256 КБ; симлинк или потенциальный секрет останавливает поиск. В модель передаются только найденные строки (до 8 фрагментов по 500 символов), а список прочитанных файлов и эти фрагменты сохраняются в контексте попытки и видны в интерфейсе. Команды, сеть и чтение вне выбранной папки не входят в этот инструмент. Перед отправкой интерфейс предупреждает о максимум двух платных POST: первый для выбора инструмента и второй с результатом. На один цикл допускается один вызов инструмента; аргументы собираются из SSE-фрагментов до разбора JSON. Ошибочные аргументы, неизвестный инструмент, повторный tool-call и неопределённый сетевой исход не запускают автоматический повтор.

## 5. История, ветки и файлы

Минимальная схема:

```text
conversations(id, title, active_leaf_id, created_at, updated_at, deleted_at)
messages(id, conversation_id, parent_id, role, content, status, model_id, created_at)
generation_attempts(id, conversation_id, user_message_id, assistant_message_id,
  model_id, request_snapshot_json, catalog_snapshot_id, status, last_seq,
  provider_request_id, provider_response_id, usage_json, cost_kind, created_at, ended_at)
attachments(id, message_id, name, mime, size, sha256, immutable_blob_path, created_at)
artifact_versions(id, message_id, previous_version_id, type, title, content,
  sha256, created_at)
model_catalog_snapshots(id, fetched_at, source, data_json)
settings(key, value)
```

`messages.parent_id` образует дерево внутри одного чата. `active_leaf_id` указывает текущую ветку. Первое сообщение имеет `parent_id = NULL`. Редактирование вопроса создаёт соседний пользовательский узел; Retry создаёт соседний ответ и новую попытку; «Продолжить» создаёт новый запрос на активной ветке. Старые узлы неизменяемы. Удаление ветки/чата — явное действие с каскадным удалением связанных вложений и Artifacts после подтверждения; нужны тесты на отсутствие висячих файлов. Artifact версионируется по `previous_version_id`; вложение — неизменяемый снимок на момент отправки, изменение исходного файла не меняет старый запрос. Для нового содержимого создаётся новое вложение. История не шифруется системным хранилищем ключа; если нужно шифрование БД, это отдельное решение и UX восстановления.

Для локального среза восстановление принимает только файл `history-*.sqlite` из каталога копий приложения. Перед заменой текущая история сохраняется новой копией; выбранная копия проверяется на целостность, внешние ключи, версию схемы и таблицы истории. Незавершённые попытки после восстановления получают статус `interrupted`. Интерфейс требует подтверждения пользователя.

Для текущего среза A4 выбранные текстовые файлы ограничены 256 КБ и пятью файлами на сообщение. Системный picker вызывается только из Rust-команды главного окна. Rust проверяет расширение, UTF-8 либо UTF-16 с BOM, размер и известные имена секретных файлов; эти проверки не гарантируют обнаружение всех секретов. До отправки пользователь видит имя, размер, SHA-256 и содержимое. После отправки исходный путь не хранится: байты неизменяемого снимка находятся в SQLite `attachments.content`, поэтому резервная копия истории включает вложения без отдельного каталога. Непосланные снимки живут только до закрытия приложения. Retry повторно использует вложения того же пользовательского узла. Это узкая реализация A4; сборка отправляемого контекста относится к A5.

Текущий срез A5 хранит нормализованные снимки публичного [каталога SimpleClaw](https://simple-claw.ru/docs/provider-api) в SQLite с временем получения и порядковым ID снимка. При открытии показывается последний снимок, затем Rust обновляет его без ключа по HTTPS с таймаутом 8 секунд; старый ответ обновления не заменяет более новый, ошибка оставляет кэш. Для выбранной модели попытка сохраняет ID модели, время каталога, снимок входной и выходной цены и точный состав контекста. Цена без поля каталога и предел контекста показываются как неизвестные. Подтверждённого справочника категорий, лимитов и токенизаторов пока нет: все модели по умолчанию относятся к «Остальным», оценка токенов не выдаётся. Пользователь может вручную отнести модель из текущего каталога к «Мышлению», «Скорости» или «Экономии»; SQLite хранит источник `user` и время правки отдельно от снимков каталога. Эта пометка не доказывает свойства модели. Каталог не доказывает пригодность каждой записи для текстового чата.

Контекст A5 собирается из пути выбранной ветки, фиксированной системной инструкции и неизменяемых снимков вложений. Незавершённый ответ ассистента исключается; при превышении локального предела 256 КБ удаляются старые завершённые пары «вопрос–ответ», не меняя историю. Если обязательная часть всё ещё больше 256 КБ, отправка блокируется. Перед локальной отправкой интерфейс требует предпросмотр точного текста и файлов; при изменении вопроса, модели, ветки или вложений его нужно получить заново. Сохранённый JSON попытки позволяет воспроизвести фактический состав, но локальный предел в байтах не гарантирует совместимость с неизвестным окном модели.

Срез A6 добавляет явную отправку `POST /v1/chat/completions` для выбранной модели. Rust читает ключ из системного хранилища, использует сохранённый снимок контекста и отправляет текстовые `messages`, `stream: true`, `max_tokens: 1024` без недокументированного `stream_options`. Redirect запрещён, адрес фиксирован, новых POST при сетевой ошибке клиент не делает. Ответ ограничен 2 МиБ, одно SSE-событие — 1 МиБ, ожидание следующего чанка — 30 с; отмена прекращает локальное чтение. Дельты сначала сохраняются в SQLite с `seq`, затем отправляются в Channel. `completed` ставится только после `[DONE]`; EOF без него оставляет `interrupted`, HTTP/SSE-ошибка — `failed`, локальная отмена — `stopped`. Сохраняются доступные серверные ID, `usage`, HTTP-статус и код ошибки; отсутствие `usage` означает неизвестное значение. Это осторожное локальное правило до подтверждения фактического SSE-контракта SimpleClaw. Retry платного запроса требует явного действия и предупреждает о возможном повторном списании.

В SQLite включить внешние ключи, ограничения роли/статуса, запрет связей между чатами и циклов на уровне проверяемых операций Rust; миграции в транзакции; WAL, одна очередь записи, пакетные обновления потока. При запуске незавершённые попытки становятся `interrupted`. Резервная копия через SQLite Backup API, затем проверка открытия и контроль содержимого. Экспорт истории отдельно от резервной копии; ключ не попадает ни туда, ни туда. Удаление ключа не удаляет историю.

Контекст запроса: путь от активного листа до корня + системные инструкции + явно выбранные версии вложений. Сначала убрать из *отправляемого* контекста старые законченные обмены; локальная история остаётся целой. Не разрывать связанные tool-сообщения, если они появятся после MVP. Резюме привязать к ветке и снимку исходного участка, показывать как источник контекста. Создавать его только по явному действию или заранее включённому режиму с понятной стоимостью. Если обязательная часть не помещается по подтверждённому пределу — остановить отправку.

Файлы: picker даёт доступ только к явно выбранному файлу. В P0 читать ограниченные по размеру UTF-8/UTF-16 текстовые форматы после проверки кодировки, показывать содержимое/размер и точный список отправляемого. Символические ссылки и путь проверять после канонизации; исключить `.env`, приватные ключи и известные секретные файлы по умолчанию, но не обещать обнаружение всех секретов. В P0 нет фонового индексирования, обхода целой папки, записи и запуска команд. Проверить лицензию каждого повторно используемого компонента до включения в сборку.

## 6. Artifacts: решение и изоляция

Artifact — локально извлечённая версия результата модели, не функция SimpleClaw. Создание: явная разметка ответа или действие «Открыть как Artifact»; code block лишь предлагает это действие, не запускает код автоматически. Исполнять только завершённую версию по явному нажатию Preview. Code/Copy/Export доступны всегда. Markdown и код выводить как текст без выполнения HTML; SVG в статическом режиме санитизировать или показывать как изображение через проверенный безопасный путь.

Интерактивный P0 ограничен **самодостаточным HTML/CSS/JS**. Нет React-сборки, npm, CDN, remote imports, `fetch`, WebSocket, service worker, локальной сети, файлов, `file:`/custom URL, системных команд, clipboard, downloads, форм, popups и навигации. Пользовательский код не получает API-ключ или IPC. Для Tauri — отдельное непривилегированное окно/webview просмотра, внутри `iframe sandbox="allow-scripts"` без `allow-same-origin`; документу задаёт CSP само приложение, а не ответ модели. CSP с `default-src 'none'`, запретом `connect-src`, `form-action`, `base-uri`, `object-src`, ограничением img/style/script только необходимыми локальными/встроенными ресурсами и `navigate-to`, если поддерживается. Дополнительно перехватывать попытки навигации, открытия окон, внешних протоколов, загрузок и сетевых запросов на уровне WebView/хоста: CSP сама по себе не закрывает все каналы. Не доверять сообщению из iframe без проверки origin и схемы; лучше не давать мост вообще. Лимит времени/размера и принудительное закрытие просмотрщика при зависании; iframe не гарантирует отдельный процесс и не заменяет ограничение ресурсов.

Перед включением интерактивного режима на Windows WebView2 и macOS WebKit провести отрицательные тесты: вызов каждой Tauri-команды из viewer и iframe; чтение ключа/файлов; `fetch`/WebSocket/изображения/формы к интернету, localhost и private IP; `file:` и custom protocol; `window.open`, top navigation, скачивание, clipboard; вложенные iframe и `srcdoc`; бесконечный цикл и рост памяти; закрытие просмотрщика; экспорт без исполнения. Проверить сетевым журналом, файловыми маркерами и отсутствием вызовов Rust, а не только сообщением JS об ошибке. Если хотя бы один обязательный тест не пройден, интерактивный режим выключен в релизной сборке. Статический fallback остаётся. Для Electron как альтернативы тестировать отдельное окно с `sandbox=true`, `contextIsolation=true`, `nodeIntegration=false`, `webSecurity=true`, без привилегированного preload и с отдельной сессией.

## 7. UI и производительность

Три области: слева чаты, центр сообщения, справа Artifact по требованию. Системные шрифты, простые поверхности, клавиатурная навигация, светлая/тёмная тема. Показывать модель на каждом ответе, состояния попыток, данные usage с источником, цену с меткой «оценка/подтверждено/неизвестно», точный перечень отправляемых файлов. `Retry` и `Продолжить` имеют разные подписи. Прерванный ответ виден и восстанавливается после перезапуска.

Конкретная компоновка и критерии переработки текущего окна описаны в [`ui-refresh.md`](ui-refresh.md). Это проектная спецификация интерфейса; она не меняет контракт данных, безопасность Artifacts и условия готовности P0 ниже.

Тема интерфейса: выбор `Системная` (по умолчанию), `Светлая`, `Тёмная` в настройках. Системный режим следует изменению темы ОС; явный выбор сохраняется после перезапуска и переопределяет ОС. Применять тему сразу, без сброса черновика и текущего потока. Окрашивать оболочку по смысловым ролям из `DESIGN.md`; пользовательский статический HTML/SVG Preview автоматически не перекрашивать.

Историю грузить частями, длинный Markdown не переразбирать целиком на каждом токене, подсветку выполнять для завершённых блоков и кэшировать результат. В отсутствие реальных измерений не утверждать выигрыш. Ориентиры исходного ТЗ — холодный старт до 3 с, открытие чата до 300 мс — становятся критериями только после фиксации тестового железа, размера БД, 95-го процентиля и обеих ОС. Добавить измерение времени до первого отображённого токена, максимальной памяти основного окна и viewer, задержки UI при длинном потоке, допустимой потери частичного ответа после аварии. Предлагаемый предел потери: не более последнего пакета сохранения (цель — 1 с/4 КБ), подтверждать crash-тестом. Числа производительности не объявлять достигнутыми до измерений.

## 8. Выпуск и критерий готовности

До реализации зафиксировать нижнюю версию Windows 10 (сборку), macOS, WebView2 и фактические тестовые компьютеры. Начальная политика продукта: Windows 10/11 x64, macOS 13+ arm64; macOS x64 — только после установки и полного smoke-теста. Это поддерживаемые **продуктом** версии, а не утверждение о минимуме Tauri. Установщик Windows должен предусматривать WebView2. Для распространения macOS вне App Store — подписать и нотариально заверить; для Windows — подпись установщика/бинарника при наличии сертификата, зафиксировать ситуацию SmartScreen. Если подписи нет, закрытый тест возможен с явной инструкцией, публичный релиз не объявлять готовым. Обновления безопасности: подписанный манифест/пакет, проверка подлинности, возможность быстро отозвать уязвимую версию и предсказуемый канал доставки; сначала можно выпускать вручную подписанные обновления, автообновление не обещать до проверки.

Готовность P0 требует реальных установок на обеих ОС, проверки keychain, SSE и восстановления, отрицательных тестов Artifacts, лицензий зависимостей, подписанных артефактов или явно ограниченного закрытого теста. Никаких платных тестов в CI. Вся документация безопасности должна описывать, что prompt отправляется SimpleClaw и далее поставщику модели, а локальная БД не зашифрована сама по себе.

A6 прошёл локальные HTTP-тесты, один разрешённый POST через Rust и две отправки из тестового окна с подтверждёнными строками списания; точные границы указаны в `checks.md`. Новые платные проверки требуют отдельного согласования расходов.

Локальный срез A7 хранит Artifact как версию завершённого ответа с `message_id`, `previous_version_id`, типом `code`/`html`/`svg`, содержимым и SHA-256 в SQLite (`user_version=7`). Панель открывает код, копирует и экспортирует версию после явного действия пользователя. Статический HTML/SVG Preview строится из очищенного содержимого в `iframe sandbox` без разрешений; CSP документа запрещает скрипты, соединения, формы и внешние ресурсы. Markdown в чате не исполняет HTML. Интерактивный viewer выключен; отрицательные проверки из раздела 6 на обеих ОС остаются условием его включения. Проверенные границы локального среза указаны в `checks.md`.

Локальный срез A8 сохраняет статический Preview как единственный режим просмотра. На macOS собран и проверен по контрольной сумме DMG для внутренней проверки, но приложение в нём не имеет подписи разработчика и нотариального заверения. Публичный выпуск блокируют подпись, установка из готового пакета и проверка на реальной Windows. Узкая отрицательная проба статического Preview описана в `checks.md`; она не заменяет обязательный набор испытаний интерактивного viewer из раздела 6.

Локальный срез P1 «Несколько бесед» использует существующие `conversations` и миграцию `user_version=8`: прежняя беседа остаётся с ID 1 и названием «Локальный чат», новые имеют собственные название, архивный статус и активную ветку. Команды чтения истории, предпросмотра контекста, отправки, Retry и выбора ветки принимают ID беседы; Rust проверяет принадлежность сообщений и не добавляет данные другой беседы в контекст. Архивная беседа доступна для восстановления, но новые запросы в ней запрещены. При переключении интерфейс по подтверждению убирает черновик и ещё не отправленные файлы. Один активный поток остаётся общим для приложения. Копия SQLite хранит все беседы; старая копия мигрирует при восстановлении. Границы проверки — в `checks.md`.

Срез P1 «Поиск и закрепление бесед» добавляет `pinned` через миграцию `user_version=9`. Закреплённые беседы идут первыми внутри активного списка и архива. Поиск без учёта регистра просматривает название и текст всех сообщений беседы, включая архивные и невыбранные ветки, и возвращает только сведения о беседе. Поиск не передаёт тексты сообщений в JS. Срез локальных проектов добавляет фильтр поиска по выбранному проекту и беседам без проекта.

Срез P1 «Локальные проекты» добавляет таблицу `projects` и связь беседы с проектом через миграцию `user_version=10`. В интерфейсе доступны создание, выбор, переименование, архивирование и восстановление проекта; беседу можно переместить между активным проектом и списком без проекта. Архивный проект остаётся доступен для восстановления, новые беседы в нём не создаются, перенос в него запрещён. Поиск ограничивается выбранным проектом либо беседами без проекта. SQLite backup включает проекты и связи, старые копии продолжают мигрировать при восстановлении. Проверки сохранности содержимого и оставшиеся границы — в `checks.md`.

Срез P1 «Материалы проекта» хранит выбранные пользователем текстовые файлы как неизменяемые версии с SHA-256 в `project_materials` (`user_version=11`). Повторное добавление файла с тем же именем создаёт следующую версию, не перезаписывая старую. Для конкретного сообщения пользователь выбирает до пяти версий проекта вместе с обычными вложениями; предпросмотр показывает версии, хеши и полный точный текст. Отправка сохраняет выбранное содержимое в беседе и сериализованный контекст попытки, поэтому последующие версии не меняют отправленное. Материалы доступны только беседам своего активного проекта; резервная копия включает библиотеку и проверяет хеши. Проверки и границы UI — в `checks.md`.

Срез P1 «Ограниченное чтение папки» сохраняет в `project_folders` (`user_version=12`) только путь, явно выбранный системным диалогом для активного проекта. Показываются лишь обычные файлы первого уровня, максимум 500 элементов; подпапки не обходятся. Список и предпросмотр сообщают размер, ограничение 256 КБ и причины блокировки. Пути с разделителями и выходом за корень, симлинки, неподдерживаемые форматы и известные имена секретов отклоняются. Перед добавлением в библиотеку хеш сравнивается с предпросмотром; если источник изменился, пользователь должен просмотреть его заново. Сведения о папке остаются локальными, автоматический поиск по диску не выполняется.

Срез P1 «Изображения» использует существующую таблицу `attachments`: файл остаётся в SQLite с MIME, размером и SHA-256 и попадает в резервную копию. Поддерживаются PNG/JPEG/WebP до 3 МиБ каждый, не более 8192 пикселей по стороне и максимум 16 мегапикселей на изображение; в полном контексте — не более восьми изображений; перед отправкой проверяется полный размер JSON (предел 5 МиБ). В интерфейсе показываются само изображение, размер и выбранная модель. Сеть принимает изображения только при выборе `gpt-6-luna`; основание — пример Chat Completions с этой моделью в [документации SimpleClaw](https://simple-claw.ru/docs/provider-api), проверенной 9 ноября 2026. Другие модели и локальный mock не принимают изображения. Пределы и точный список форматов подтверждены этой документацией; наличие модели в каталоге не считается подтверждением поддержки.

Срез P1 «Сведения о моделях» показывает цены и время загрузки из снимка каталога, ссылаясь на Provider API. Для параметров, которых каталог не сообщает (контекстное окно и токенизатор), интерфейс явно пишет «неизвестно» и не оценивает токены по байтам. Возможность работы с изображениями приписывается только модели, приведённой в примере API; для остальных она неизвестна. Предупреждение о неизвестном лимите и возможных расходах видно до отправки. Пользовательские категории хранятся отдельно от снимка и переживают его обновление.

Срез P1 «Палитра команд» открывается сочетанием `⌘K`/`Ctrl+K`, позволяет найти основные действия беседы и выбрать их стрелками/Enter. Сочетание игнорируется внутри полей ввода. Закрытие возвращает фокус к вызвавшему элементу; команды перевода фокуса задают целевое поле или чат. Палитра не добавляет новые возможности отправки и не включает интерактивные Artifacts.

Срез P1 «Стиль ответа» хранит значение `concise`/`balanced`/`detailed` в SQLite и добавляет соответствующую инструкцию в системное сообщение следующего контекста. Стиль и инструкция сохраняются в `context_json` попытки, а предпросмотр показывает выбранный режим. Изменение настройки не переписывает историю или ранее сохранённые контексты; во время активного потока контрол настройки отключён.

Срез P1 «Сохраняемый цикл действий» — только локальная демонстрация из трёх синтетических шагов. Предложение, решение и результат записываются в SQLite; каждый следующий шаг появляется только после разрешения предыдущего. Отклонение завершает задачу. Перезапуск и восстановление из копии возвращают ожидающий шаг без автоматического выполнения. Этот срез не запускает реальные инструменты, команды, сеть или платные запросы.

Срез P2 «План, очередь и смена направления» хранит плановые шаги, очередь запросов и уточнения отдельно для каждой беседы (`user_version=15`). Шаг плана можно отметить выполненным только один раз; нормализованный повтор действия, запроса или уточнения отклоняется, в том числе если действие плана уже выполнено. Во время ответа новое уточнение сохраняется локально. «Вставить в черновик» только копирует выбранный текст в обычное поле ввода; запрос отправляется лишь после проверки контекста и явного нажатия «Отправить». Следующая запись очереди автоматически не запускается. Все три таблицы включены в backup/restore.

Срез P2 «Первый локальный навык» выбирает только уже добавленный пользователем Markdown-материал активного проекта до 16 КиБ. Выбор и включение — разные явные действия; источник, версия, SHA-256 и текст видны в интерфейсе. Включённый навык помещается отдельным пользовательским сообщением в неизменяемый снимок только агентного контекста. Остальные режимы и контексты не получают его текст; отключение действует на следующий снимок и не переписывает сохранённый. Набор tools, проектная область чтения, команды и сеть не меняются. Навык хранится для беседы и входит в backup.

Срез P1 «Генерация изображения» использует только модели с протоколом `images_generations` из публичного каталога. Перед отправкой показываются SimpleClaw, модель, цена за запрос и время каталога; неизвестная цена блокирует кнопку. Rust повторно загружает публичный каталог и сверяет подтверждённую цену до платного POST. Запрос делается только после отдельного подтверждения пользователя, один результат PNG можно сохранить через системный диалог. При неизвестном сетевом результате повтор той же комбинации модели/описания блокируется; для нового запроса нужно изменить описание или модель. Ключ берётся только в Rust из системного хранилища.

## Локальный вертикальный срез (4 ноября 2026)

Реализация среза использует один локальный чат и один активный mock-запрос. `start_mock_generation(prompt, on_event)` принимает только текст до 2000 символов; сетевого POST и ключа нет. Rust формирует синтетический SSE, разбирает его по полным событиям и отправляет через Tauri Channel события `delta { attempt_id, seq, text }` и `end { attempt_id, status }`. Успех возможен только после `[DONE]`; обрыв без него — `interrupted`. `stop_generation` ставит локальный флаг остановки. `list_history` читает SQLite. Команды разрешены capability только окну `main` через `AppManifest::commands`.

До миграции схема локального среза содержала только `messages` и `attempts`; при запуске незавершённые записи становились `interrupted`. Каждая дельта сохраняется транзакцией до отправки в UI. Это намеренно узкая реализация для проверки потока и восстановления; вложения из раздела 5 ещё не готовы. Реальные модели, платные запросы, агентные инструменты и Artifacts не входят в срез. Отдельный `viewer` создаётся только с тестовым конфигом `src-tauri/tauri.viewer-test.conf.json`; обычная сборка его не открывает. Первоначальная проверка подтвердила отказ трёх команд потока и истории; тестовое окно теперь пробует девять команд, включая ключ, backup и ветки, но новая сборка ещё не проверена в запущенном приложении.

Начало A3–A4: на macOS проверен CRUD синтетического секрета во временной связке Keychain. Rust-команды `save_key`, `delete_key`, `key_status` обращаются к системному хранилищу через `keyring`; статус возвращает только факт наличия, чтения ключа в JS нет. Команды включены в `AppManifest` и capability только окна `main`. Логика прошла mock-тест, а нативная запись, замена и удаление синтетического ключа прошли Rust-тест вне песочницы; в песочнице Keychain возвращает ошибку авторизации. Вызов из запущенного главного окна и отказ из нового viewer ещё не проверены. Тестовая сборка viewer использует отдельный идентификатор приложения, отдельный профиль данных и отдельную запись Keychain. Миграция `user_version=0 → 1` переносит существующие `messages` и `attempts` в одну беседу, выставляет `parent_id` по порядку старых пар «вопрос–ответ» и сохраняет частичный ответ; новые mock-пары продолжают цепочку. SQL проверен на синтетической копии старой схемы; Rust-тесты прошли как в памяти, так и на старой файловой базе после повторного открытия. Запуск приложения с миграцией ещё не проверен. Команда `create_backup` делает снимок через SQLite Backup API в каталоге данных приложения, проверяет открытие, целостность, внешние ключи и контрольные показатели содержимого; тест на синтетической БД с частичным ответом прошёл. Локальный Retry теперь создаёт соседний ответ и новую попытку от того же пользовательского узла; выбор старого ответа меняет активную ветку, а новая пара продолжает её. Список всех ответов позволяет вернуться к скрытым продолжениям; смена ветки заблокирована на время потока. Статусы сообщения и попытки завершаются одной транзакцией. Это проверено тестами БД и сборкой интерфейса, но ещё не проверено нажатием в запущенном приложении. Вложения из раздела 5 ещё не готовы.
